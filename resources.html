01Agentic migration tooling

Anthropic's migration method and kit

A blog post worth studying, and its companion repository
What
A six-step method from running million-line migrations with Claude Code: build a rulebook of translation decisions and a dependency map → stress-test the rules on three files and throw the output away, keeping the improved rules → translate in parallel batches with adversarial reviewers → compile, test, and diff behaviour. The companion repo packages it: eight paste-ready prompts, a rulebook template, queue-runner and build-daemon scripts, one worked example.
The line to steal
“Validate the judge first” — prove the harness passes the original code and fails deliberately broken code before migrating anything. The same rule our engagement earned through eight failures, stated as step zero.
Watch out
The kit defaults to structure-preserving migrations — same design, new language. If you are redesigning as you migrate, its own README says which parts change and which become invalid. Reference code, not a maintained product.

The code-modernization plugin for Claude Code

The full lifecycle, as slash commands
What
An installable plugin enforcing the sequence migrations die by skipping: preflight → assess → map → extract-rules → brief → (transform | reimagine | uplift) → harden. Discovery writes reviewable artifacts; a human approves the brief before any code is generated; the transform command writes characterization tests before the implementation and proves equivalence after.
Why it matters
It encodes the discipline this whole site argues for. Our engagement ran its discovery half early and then re-invented its transform discipline by hand — use it as designed instead.

02Four books

BookWhyOne idea to steal
Working Effectively with Legacy Code
Michael Feathers, 2004		 The origin of characterization testing and seams. Twenty years old; still the best account of changing code you cannot yet test. “Legacy code is code without tests” — by that definition, a rebuild outrunning its checks is legacy code on the day it is written.
Monolith to Microservices
Sam Newman, 2019 · samnewman.io		 The migration-patterns catalogue: strangler fig, parallel run, branch by abstraction, and the shared-database chapters. In a parallel run, exactly one side is ever the source of truth — and mismatches are data, not failures.
Kill It with Fire
Marianne Bellotti, 2021 · No Starch		 The strategy book: when to modernize at all, how these projects lose momentum, and why the hard part is the system around the system. Her test for progress: does this step reduce risk this quarter, or only promise to?
Technical Agile Coaching with the Samman Method
Emily Bache, 2021		 If you want to teach these techniques to a team rather than only apply them. Run the Gilded Rose kata as a team hour — it teaches approval testing in ninety minutes.

03A reading order

Shortest useful path, timed honestly.

  1. Feature Parity — the warning label for every rebuild-to-parity project. ~15 min
  2. Approval tests at understandlegacycode.com — the fastest practical intro. ~15 min
  3. Anthropic's migration write-up — rulebook, stress-test, validate the judge. ~20 min
  4. Scientist's README + Zalando's parallel-run post — shadow verification in production. ~30 min
  5. Patterns of Legacy Displacement, the full series — over a week, not a sitting. ~3 h
  6. Working Effectively with Legacy Code chs. 1–5 and 13, then Monolith to Microservices chs. 3–4, then Kill It with Fire end to end. books
The thread through all of it

From Feathers in 2004 to automated million-line migrations in 2026, every serious source arrives at the same sentence: the migration is only as good as the thing that judges it. Build the judge first, make sure it can say no, and the rest is throughput.
